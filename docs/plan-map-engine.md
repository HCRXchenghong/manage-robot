# 点云地图引擎功能规范

地图引擎负责真实点云资产的导入、校验、转换、编辑、分块、发布和回滚。原始
数据内容寻址且只读，任何转换或编辑都生成新版本；地图版本是任务和车辆发布
状态的依赖，不能被静默覆盖。

## 资产与版本模型

```text
上传/车端上报
      ↓ SHA-256 + 格式/坐标/范围校验
原始版本（只读）
      ├─ 3D 转换 → 2D 栅格版本（PNG/PGM/YAML）
      ├─ 编辑差异 → 新 2D 版本
      └─ 分块作业 → COPC/3D Tiles 资产
      ↓ 审核、兼容性与 ODD 校验
车辆发布 → 回执确认 → 可回滚到已审核版本
```

每个版本记录来源、作者、创建时间、内容摘要、坐标系、分辨率、边界、工具版本、
父版本和发布回执。对象存储保存大文件，PostgreSQL/PostGIS 保存元数据、空间索引、
审核和发布关系。

## 数据处理

- 输入支持受控的 PCD、CSV、LAS/LAZ 和栅格格式；必须校验大小、扩展名、文件头、
  坐标范围、NaN/Inf、点数和压缩炸弹风险。
- 小型受控文件可由 `map-engine/tools/` 工具处理；生产大文件进入隔离 Worker，
  Worker 资源、超时和临时目录均有上限。
- 3D→2D 采用高度切片和占据投影；输出 PNG、PGM、YAML，明确分辨率、原点和坐标系。
- 浏览器使用分块数据和层级细节渲染；超出点数预算时服务端降采样，不改变原资产。
- 编辑只保存擦除、恢复、分类和禁行/缓行矢量差异，不改写原始点云。

## 服务接口

- `GET /api/maps`：返回当前会话可见地图及版本链。
- `POST /api/maps/upload`：保存新原始版本，按车辆和内容摘要去重。
- `POST /api/maps/{id}/convert`：创建 3D→2D 派生版本。
- `GET /api/maps/{id}/points`：按版本和点数上限返回真实点云切片。
- `POST /api/maps/{id}/edit`：保存新编辑版本。
- `DELETE /api/maps/{id}`：按权限删除服务器资产；车辆原始文件不受影响。

地图上传、转换、编辑、审核、发布、回滚和删除都必须带人员、车辆、组织、trace
和审计记录。地图缺失或未通过校验时，任务调度和车辆发布必须拒绝。
