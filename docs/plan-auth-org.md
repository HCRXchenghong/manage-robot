# 身份、组织与访问控制功能规范

本文件定义运营平台的人员身份、组织隔离、设备绑定和登录安全约束。实施进度
只记录在 [`implementation-progress.md`](implementation-progress.md)。

## 登录与会话

账号密码登录采用两步流程：账号密码校验通过后，服务端发放一次性预认证令牌；
第二步完成服务端图形验证码后创建 HttpOnly、SameSite=Lax 会话 Cookie。

- 密码至少 8 位，包含大写、小写、数字、符号至少三类。
- 新密码使用带随机盐的 PBKDF2-HMAC-SHA256；旧哈希只用于受控迁移。
- 连续失败 5 次锁定 30 分钟；图形验证码 5 分钟有效，错误 3 次作废。
- 会话闲置 30 分钟或绝对存续 8 小时失效；改密使其他会话失效。
- 登录、失败、锁定、登出、改密和会话撤销均写入审计。
- 手机号登录只有在真实短信供应商配置后才能启用；未配置时不得生成或展示
  本地验证码。

## 角色与组织

| 角色 | 资源范围 | 管理能力 |
|---|---|---|
| `super` | 全部组织与车辆 | 管理组织、用户、设备、开放 API 和平台配置 |
| `group_admin` | 所属组织 | 管理所属组织成员和资源，不得跨组织授权 |
| `user` | 所属组织 | 使用被授权的车辆、任务、地图和只读运维能力 |

组织是车辆、地图、路线、事件和工作空间会话的隔离边界。服务端必须以数据库
关系执行授权，前端过滤只用于界面体验，不能作为安全边界。

## 受信控制设备

控制设备绑定到人员账号，绑定状态与在线状态分离。设备只有在真实控制代理完成
设备证明、心跳和吊销检查后，才可参与接管租约申请。浏览器键盘、方向盘或一体机
输入都必须经受信控制代理进入双链路控制面。

## 开放 API

API Key 仅保存摘要，明文只在创建响应中返回一次。每个 Key 必须配置功能范围、
车辆白名单、来源 IP/CIDR、有效期和负责人；调用使用 HMAC、时间戳、一次性 nonce
和请求体摘要。鉴权成功、失败、重放、越权、锁定和撤销均进入审计。

## 运行边界

没有 PostgreSQL 时，服务只能进入显式的 volatile 只读诊断模式；该模式不恢复本地
身份文件、不允许业务写操作、不签发租约、不执行急停，也不提供默认账号或默认车辆。
